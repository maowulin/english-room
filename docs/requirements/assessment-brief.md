# 实作题需求解读

## 项目背景

本项目来自一份开发岗位候选人实作题。目标是在约 3 天内完成一个可运行、可录屏讲解的多人英语实时语音房间 Demo。

原始题目副本保存在 `docs/source/腾讯云在线房间与英语评分_候选人实作题.docx`。

## 核心业务闭环

1. 多名玩家进入同一个在线房间。
2. 玩家在房间内进行实时英语语音交流。
3. 系统能够区分玩家并处理各自的英语语音。
4. 房间结束后，为每名玩家创建异步口语评分任务。
5. 客户端展示玩家、评分状态、评分结果和必要的局内表现信息。

## 功能要求

### 多人房间

- 创建或加入一个房间。
- 展示当前房间成员。
- 同步玩家加入、离开和断线状态。
- 确保每名玩家具有稳定且唯一的业务 ID。

### 实时语音

- 玩家能够进入同一个腾讯云 TRTC 房间。
- 玩家能够发布自己的麦克风音频。
- 玩家能够收听其他在线玩家的音频。
- 客户端能够展示本地麦克风及远端玩家的基础媒体状态。

### 局后评分

- 房间结束后触发评分流程。
- 每名玩家具有独立的音频引用和评分任务。
- 评分任务至少支持 `waiting`、`processing`、`success` 和 `failed` 状态。
- 客户端能够将评分结果对应到正确玩家。

### 演示和说明

- 提供约 8—12 分钟的录屏。
- 展示项目启动、进入房间、实时语音、结束房间和评分结果。
- 展示至少一个等待、处理中或异常状态。
- 解释架构、数据流、技术取舍和正式产品仍需补充的能力。

## 已确认的技术决策

- 客户端使用 React Native Expo。
- 因为 TRTC React Native SDK 包含原生模块，客户端使用 Expo Development Build，不依赖 Expo Go。
- 后端使用 Python FastAPI，不使用 Next.js 或 Node.js 后端。
- 业务后端不转发实时音频流。
- 腾讯云密钥只允许存在于后端运行环境，不得提交到公开仓库。
- 项目采用三个职责独立的仓库：公开 App、私有 FastAPI 后端和私有运营平台。
- 最终只交付公开 App 仓库；App 必须能够通过 Fake 适配器独立运行。
- 正式 App 包含 Sentry 和业务事件采集，不包含运营 UI、管理 Token 或私有平台查询凭证。

## 当前基础框架验收

本阶段需要满足：

- Expo 客户端能够启动。
- 在设备、模拟器或其他可验证的 Expo 运行环境中打开 Demo 页面。
- FastAPI 服务能够启动并返回健康检查结果。
- 后端代码为后续鉴权、房间和评分任务提供清晰模块边界。
- 客户端和后端均有自动化测试与类型检查。
- 仓库不包含真实腾讯云密钥、令牌或其他敏感配置。

## 本阶段不实现

- 真实腾讯云 TRTC 入房和音频传输。
- 真实腾讯云口语评测调用。
- 云端录制、对象存储和音频切片。
- Redis、消息队列或多实例部署。
- 正式账号体系、付费、监控和生产发布。

这些能力会在基础框架通过验证后按风险和演示价值逐步加入。
