# 轮流发言与个人评分隔离设计规格

## 目标

多人房间按入房顺序轮流发言。只有当前发言人可以结束自己的回合；所有成员完成回合后，且仅房主可以结束房间并进入评分。报告接口只返回当前登录玩家自己的评分、识别文本和失败状态。

## 服务端状态真相

`rooms` 增加轮次状态字段：当前发言人、当前轮次索引、已完成轮次数。房间从 `lobby` 进入 `live` 时，当前发言人设为最早加入的成员；单人房间同样需要先完成自己的回合。轮次完成由服务端校验当前玩家和房间版本，完成后原子推进到下一位。最后一位完成后保持 `live`，但标记所有轮次完成；房主此时才可以 `end`。

新增 `POST /v1/rooms/{room_id}/turn/complete`，使用现有 `room_version` 并广播实时房间快照。非当前玩家、非成员、非 live 房间或版本过期均拒绝。`end` 在已有房主校验之外增加“所有轮次完成”校验。

## 客户端交互

REST 和 WebSocket 快照携带轮次状态。Live 页根据服务端的 `current_speaker_player_id` 显示 `Your turn` 或当前玩家姓名；只有当前玩家显示并启用 `Finish turn`，其他玩家看到等待提示。房主在最后一位完成前看到禁用的 `End room`，其他玩家不显示结束操作。完成回合后所有客户端通过实时快照同步。

## 评分隔离

报告路由使用当前 Bearer 玩家身份调用报告服务，查询 `score_jobs.player_id` 必须等于当前玩家。服务端不依赖 App 隐藏其他行来实现权限隔离；Fake 客户端和 Web 视觉测试也只展示当前玩家自己的报告。

## 错误与兼容

旧数据库通过启动迁移为新字段设置安全默认值。旧客户端忽略新快照字段仍可进入房间，但无法完成回合；当前 App 使用新接口。所有状态变更继续使用 `version` 防止并发覆盖，409 映射为现有冲突提示。

## 验证标准

- 两个游客按加入顺序只能由第一个完成回合，再由第二个完成回合。
- 第二个游客不能在第一个完成前完成回合；任意游客不能提前结束房间。
- 最后一位完成后只有房主可以结束，结束后两个游客各自只能读取自己的评分。
- 单人房间完成一次回合后房主可以结束。
- 后端单元/API 测试、App 单元测试、TypeScript、Ruff、Mypy、lint 全部通过。
