# English Room UI 严格还原规格

## 目标

在 390×844 移动视口下，将 English Room 的登录、房间大厅、等待房间、实时语音房间和局后报告还原到 `docs/design/mockups/` 的信息层级、色彩、间距、卡片形态和状态表达，同时保留现有 guest session、房间状态、WebSocket、结束房间、评分轮询和重试行为。

## 约束与取舍

- 当前后端只有 guest session；登录页完整展示设计稿中的邮箱、密码和第三方入口，但 Demo 提交仍调用现有 `POST /v1/guest-sessions`，并通过开发态说明避免误导。
- RN Web 继续使用 Fake RTC；视觉上还原真实房间，不伪造真实媒体能力。实时页的媒体状态仍来自现有 `mediaState`。
- 不修改 API、状态机或评分数据结构；不把设计稿整屏当作静态背景，交互控件必须保持原生可访问组件。
- 设计稿中没有独立导出的插画资源，因此优先复用现有 mockup 资源与轻量的 RN 图形层；资源无法拆出时，用同色块、渐变和装饰边框保持布局，不改变业务信息。

## 页面要求

1. 登录/注册：品牌、灯塔雾景、欢迎文案、封面区域、邮箱/密码字段、密码显隐、忘记密码、登录按钮、Apple/微信入口和注册切换；Demo 仅在辅助说明中出现。
2. 大厅：港口故事卡、房间码、头像组、玩家/时长信息、加入/创建/输入房间码三个操作和底部导航。
3. 等待房间：返回、标题、房间码/分享、故事横幅、4×6 玩家席位、头像与状态徽章、麦克风提示、测试麦克风和开始故事底栏。
4. 实时房间：深色港口氛围、房间状态、四人头像区、发言/静音/重连状态、线索卡、信号条和麦克风/扬声器/更多/结束控制栏。
5. 报告：故事信息卡、总分环、表现文案、四项指标条、改进建议、玩家排名和处理中/失败/重试状态。

## 验收标准

- 390×844 浏览器逐屏检查，无横向溢出；底部安全区和固定操作栏不遮挡内容。
- 页面主要结构、标题层级、背景色、卡片圆角、按钮高度、状态颜色和信息顺序与对应设计稿一致。
- 现有页面测试、typecheck、lint 全部通过；浏览器仍能完成 guest → 创建 → 准备 → 开始 → 控制 → 结束 → 报告/重试流程。
