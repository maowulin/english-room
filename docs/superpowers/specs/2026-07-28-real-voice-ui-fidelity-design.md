# English Room 高保真 UI 与真实语音验证设计

## 背景

English Room 当前已经具备登录、房间大厅、等待房间、实时语音房间和局后报告的页面闭环，但 390×844 Web 截图与 Android 真机仍暴露出明显的视觉和产品问题：

- 登录页 `Enter as Demo guest` 只有 24 px 高，像临时调试入口。
- 大厅头像从设计稿中的重叠头像组裁切，原图内相邻头像已经遮挡当前头像，无法通过调整圆角修复。
- 等待页横幅中的 `The prologue begins when everyone is ready` 缺少完整的居中构图。
- `Test microphone` 实际承担准备操作，与 `Start story` 的语义重复。
- Live 页顶部连续堆叠房间标题、进度、连接状态和计时，信息相互挤压。
- Live 页 `More` 是禁用的空操作，没有产品价值。
- 当前 `.env.local` 使用 `demo` 媒体模式。Web 与 Demo APK 只能验证页面状态，不能证明真实语音、云端录音和评分流程。

本次改造以 `docs/design/mockups/01-room-entry.png` 至 `06-register.png` 为主模板，重建英文响应式页面，并交付一个默认使用真实媒体链路的 Android APK。

## 目标

1. 在 390×844 主视口下高保真还原设计稿的视觉层级、氛围、间距和卡片结构。
2. 支持 360–430 dp 宽度及当前 1080×2400 Android 真机，无重叠、截断或不可控换行。
3. 房间保持最多 6 人的产品结构，只展示真实已加入成员，同时允许房主单人开始。
4. 使用真实后端和 TRTC 跑通麦克风授权、入房、本地音频、云端录音、评分和报告。
5. 保留现有状态机、API 接口、实时同步和评分轮询行为，不覆盖无关工作树改动。

## 非目标

- 不实现账号注册、邮箱验证码、Apple 登录或微信登录的真实服务端能力。
- 不增加无后端支持的头像上传、个人资料或房间列表功能。
- 不伪造远端成员、语音活动、识别文本、录音结果或评分。
- 不提交、推送或部署代码。

## 设计原则

- 设计稿决定视觉语言，英文内容决定响应式排版。
- 真实状态决定 UI；没有 SDK 或后端证据时不展示成功状态。
- 页面只提供可执行操作，不保留装饰性的空按钮。
- 头像素材和状态图标职责分离。头像本体不包含麦克风、皇冠或状态按钮。
- 所有产品图标使用 `AppIcon` 或同一正式图标体系，不使用 Emoji 或特殊字符冒充图标。

## 页面设计

### 登录页

- 保留品牌、`Welcome back`、雾港封面、邮箱、密码、忘记密码、主登录按钮、第三方入口和注册切换。
- 普通 `Log in` 继续只显示 `Account sign-in is not available yet.`，不得创建 guest session。
- Demo guest 使用 48 px 高的全宽次级按钮，采用浅色填充、清晰边框和正式入口图标。
- 按钮文案使用 `Continue as Demo guest`，这是唯一允许出现可见 Demo 叙事的入口。
- 登录页内容在较矮视口允许滚动，底部账号切换入口必须可达。

### 注册页

- 保留返回、品牌、`Create account`、三步进度、名称、邮箱、验证码、密码、创建按钮和登录切换。
- 不显示 Guest 入口。
- 普通创建按钮继续只显示账号注册暂不可用的产品化反馈。
- 所有字段和按钮满足至少 44 px 的触控高度。

### 房间大厅

- 保留故事卡、房间状态、玩家数、预计时长、加入、创建、输入房间码和底部导航。
- 故事卡只显示当前真实用户头像。
- 空余容量使用 `5 open seats` 等文本徽章表达，不用虚假头像填充。
- 新头像必须是独立生成的方形素材，人物面部位于中央安全区，圆形裁切后不得遮挡额头、下巴或头发主体。
- `Join voice room` 只有输入有效房间码后才启用；空值状态必须在视觉上明确。

### 等待房间

- `Harbor Mystery` 保持单行，必要时使用受控字号缩放，不得与装饰线重叠。
- 房间码和分享按钮保持独立触控区域。
- 故事横幅采用对称装饰线和居中构图。正文最多两行，水平和垂直居中。
- 席位区固定表达 6 人容量。实际成员显示独立头像和准备状态，其余显示 `Open seat` 与 `Waiting to join`。
- 头像本体不叠加麦克风按钮。麦克风状态通过独立信息卡表达。
- 底部左侧按钮统一为 `Ready`：
  - Real 模式先完成权限、RTC grant 和 TRTC 入房。
  - 成功后才允许提交准备状态，并显示 `Ready`。
  - 失败时显示 `Retry voice connection`，不得显示准备成功。
- 底部右侧为 `Start story`。房主准备完成且媒体已连接后启用；只有 1 名成员时也可开始。

### 实时语音房间

- 顶部使用三列结构：左侧离开、中央标题与连接状态、右侧留空，不保留 `More`。
- 房间标题、`Voice connected` 和计时分三层显示，保持明确间距。
- 参与者区域只展示真实成员：
  - 1 人时使用居中的大头像。
  - 2 人时使用双列。
  - 3–6 人时切换紧凑网格。
- 发言光环、静音、重连和网络质量只由 TRTC 回调驱动。
- 线索卡保留 `Act II · The Pier`、`Your clue`、主线索和英文完成提示。
- 增加独立语音输入状态条：
  - RTC 已连接但尚未检测到声音时显示 `Listening`。
  - 收到非零本地语音活动后显示 `Your voice is being received`。
  - 断线、静音或权限失败时显示对应真实状态。
- 底部只保留 `Mute`、`Speaker`、`End room`。

### 局后报告

- 保留房间信息、总分、评价、四项指标、练习建议、玩家结果和返回大厅。
- 只使用真实后端返回的报告项目。
- 缺失的 Completeness 或 Vocabulary 显示 `—`，不得用其他分数补齐。
- 真实模式下只有评分任务全部完成后才显示成功评价。
- 录音、评分超时或失败时显示内联状态和可用的重试操作。

## 头像资产

使用内置图像生成能力生成一组风格一致的独立头像，保存到 `apps/mobile/assets/design/`：

- 用途：移动端圆形成员头像。
- 画面：单人肩部以上肖像，头部和发型完整，脸部位于中央。
- 风格：与雾港悬疑故事一致的精致写实插画。
- 背景：简洁、低对比度、无文字、无图标。
- 安全区：人物主体距离四边保留足够空间，适配 1:1 圆形裁切。
- 禁止内容：麦克风、皇冠、状态徽章、水印、边框和其他人物。

生成多个头像时，每个头像使用独立生成调用。最终仅保留通过视觉检查的项目资产，不引用生成工具默认目录中的临时文件。

## 真实语音数据流

1. 用户通过后端创建 guest session，并创建或加入房间。
2. App 请求 Android `RECORD_AUDIO` 权限。
3. App 从后端获取 RTC grant。
4. `TrtcNativeClient` 调用 `enterRoom`，等待成功的 `onEnterRoom`。
5. App 调用 `startLocalAudio`、设置扬声器路由并启用音量检测。
6. 只有上述调用成功后，媒体状态才进入 `joined`。
7. 用户提交 `Ready`；房主可在单人状态下开始房间。
8. Live 页订阅网络质量、远端成员、音频可用性和语音音量回调。
9. 用户结束房间后，App 调用真实 `endRoom`。
10. 后端完成云端录音处理和评分任务，App 轮询报告接口直到完成、失败或超时。
11. 报告页显示真实评分和识别文本；失败状态不得回退到 Demo 数据。

最终 release APK 默认使用 `EXPO_PUBLIC_MEDIA_MODE=real`。Real 模式不得自动回退到 `FakeRtcClient`。

## 错误处理

- API 冲突、权限拒绝、RTC grant 失败、TRTC 入房失败、网络断开、录音失败和评分失败必须在对应页面显示内联产品化反馈。
- 不在页面顶部显示裸异常字符串或会挤压主布局的错误条。
- 可恢复的媒体错误提供 `Retry voice connection`。
- 正在提交、入房、开始或结束时禁用重复操作。
- 错误文案不得泄露 SDK 参数、UserSig、服务器内部信息或原始堆栈。

## 响应式与安全区

- 主基准为 390×844，补充检查 360、393 和 430 dp 宽度。
- 标题优先单行，并通过 `numberOfLines={1}`、`adjustsFontSizeToFit` 和受控最小缩放保证安全。
- 横幅正文最多两行。
- 卡片文本容器使用 `minWidth: 0`、`flexShrink` 和明确行数限制。
- 固定底栏使用 Safe Area inset；滚动内容预留底栏高度。
- Live 页主体使用剩余空间建立视觉重心，不用固定空白撑开页面。

## 测试策略

### TDD

生产代码修改前先添加并运行失败测试，至少覆盖：

- Demo guest 按钮使用正式全宽次级样式。
- 登录与注册页保持正确入口边界。
- 大厅不再引用重叠头像裁切表。
- 等待页标题单行、横幅居中、席位文本受控。
- `Ready` 替代 `Test microphone`，单人准备后可开始。
- Live 页不存在 `More`，只保留 3 个控制项。
- Live 页只渲染真实成员。
- 语音活动文案只在真实回调后出现。
- Real 模式不回退到 Fake RTC 或 Demo 报告。

每个测试必须先因缺少目标行为而失败，再用最小生产改动使其通过。

### Web 视觉回归

在手机视口逐页完成并截图：

- 登录。
- 注册。
- 大厅空房间码和已输入房间码。
- 等待页未准备、已准备和媒体错误重试。
- Live 页连接、检测语音、静音、取消静音、扬声器切换和重连。
- 报告处理中、完成和失败。

Web 仅用于布局与交互回归，不作为真实语音证据。

### Android 真机回归

主链路必须通过正常 UI 操作完成，不使用 QA 路由代替：

1. 登录。
2. 创建房间。
3. 授权麦克风。
4. TRTC 入房。
5. 准备。
6. 单人开始。
7. 对麦克风说出可识别英文。
8. 验证非零本地语音活动。
9. 验证静音和扬声器操作。
10. 结束房间。
11. 等待真实录音和评分。
12. 验证报告任务完成且识别文本非空。

真实语音通过必须同时具备：

- 成功的 TRTC 入房回调。
- 非零本地语音活动证据。
- 后端录音与评分任务完成。
- 非空识别文本。

缺少任一项时，不得宣称真实语音流程跑通。

TypeScript 改动后运行：

```bash
npm test -- --runInBand
npm run typecheck
npm run lint
git diff --check
```

随后构建 release APK、安装到目标 Android 真机，并完成 Web 与真机逐页截图回归。最终交付一个默认使用真实媒体模式的 APK，并报告真实语音证据、APK 路径和仍存在的外部阻塞。
